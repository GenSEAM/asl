One row per finding in both reviews, plus the risk-verification rows, the "what would slip through"
items, and the one cross-phase constraint from `.plans/ORCHESTRATOR-LOG.md`.

took a different one, the row is `accept-modified` and names the declined half with the evidence
that settled it. Every disagreement between the two reviews, or between a review and the plan, was
settled by opening the file or running the command — never by averaging.

Notation: `W<n>` refers to **v2** work items unless prefixed `v1`.

## Cross-phase constraint (`.plans/ORCHESTRATOR-LOG.md`)

| # | source | constraint | disposition | where it landed |
|---|---|---|---|---|
| O1 | orchestrator log | Phase 1 owns the **whole** `defenum` Rust codegen fix; Phase 2 independently found 8 builtins (`list-sort`, `list-min`, `list-max`, `map-has?`, `map-remove`, `map-keys`, `map-pairs`, `map-from-pairs`) blocked by that lowering missing `Ord`/`Eq` derives. Phase 2 is not re-planning it | **accept** | W2.4. Not folded in as a note — scoped with measurement, because the obvious implementation does not compile: `#[derive(Debug, Clone, PartialEq, Eq, PartialOrd, Ord)] pub enum Shape { Circle(f64), … }` gives `E0277: the trait bound f64: Eq is not satisfied` (and the same for `Ord`). The rule is therefore **conditional**: derive `Eq, PartialOrd, Ord` only when no field or case-parameter type is transitively `Float64`; a bare type variable does not block it, because derive emits its own `T: Eq` bound (verified — `#[derive(Eq, Ord)] pub enum Tree<T> { Leaf, Node(T, ::std::boxed::Box<Tree<T>>, …) }` compiles). The same rule repairs `backend/to_rust.py:128`, whose unconditional `Eq`/`Ord` on `defschema` is the mirror-image latent bug Phase 2's plan flagged (`.plans/phase-2/PLAN.md:166-171`). The transitivity computation over user types, against the emitter's enum→schema→fun ordering (`backend/to_rust.py:99-109`), is recorded as a hazard in §6.1. |

## Things v2 asserts that neither review supplied

Recorded so they are not mistaken for review findings.

1. **`Clone` bounds on `defun` type parameters are mandatory, and the exec review's W7 milestone is
   wrong without them.** Measured: `pub fn swap<A, B>` → 2 new `E0599` errors (13 → 6);
   `pub fn swap<A: Clone, B: Clone>` → 13 → 4. §1.7, W2.2, and §6.1 records that there is no bound
   inference beyond `Clone` — a generic `defun` using `=`, `<` or `list-sort` over a type variable
   still will not compile and no fixture exercises it.
2. **The `Eq`/`Ord` derive must be conditional**, with the `f64: Eq` failure measured. O1 above.
3. **`backend/t/smoke.agents:3` has the same rule-13 violation as `06-module.agents`** (`area
   [(sh Shape)]` exported, `Shape` not). No checker gate covers that file; fixed in W14.3 so the
   tree contains no known violation.
4. **Two existing semantic fixtures report two codes**, which is what forced F9's opt-in mechanism
   rather than a blanket assertion.
5. **`AGENT_SPEC_CORE.md:659`** ("Rules 2, 5, 6, 7-12 are semantic") has to become `7-13` when rule
   13 lands. W1.

3. **[non-blocking] The grep gate in Item 3 misses a class of identifier leaks.** The pattern `tree.sitter|tree_sitter|QUERY|run_query|subprocess` will match any literal containing the substring `tree-sitter` (because `.` is regex-any), but a hypothetical variable named `query` or `sub` (the lowercase forms the plan does not introduce) would slip through. The gate's effectiveness rests on the delete list being complete; if an implementer left a stray variable or string literal with one of the listed tokens in any case other than what the plan names, the grep would still catch it (it is case-sensitive only on `QUERY|run_query`, not on `tree.sitter|tree_sitter`). Acceptable as-is.
